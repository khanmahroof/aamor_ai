# Aamor Chat

A local-first AI chat app built with Next.js App Router, React, TypeScript, Prisma and SQLite. Ollama provides local inference; OpenAI and Anthropic are optional server-side integrations.

## Start here

Requires Node.js 24 LTS with npm. Run these commands from this project folder:

```powershell
npm ci
npm run setup
npm run dev
```

Setup creates `.env` if missing, generates a private authentication secret, applies database migrations and generates Prisma Client. It preserves existing configuration and data. Open http://localhost:3000, create an account, and sign in. No seeded password or paid API key is required.

### Enable local AI replies

1. Install Ollama from https://ollama.com/download/windows.
2. Open a terminal and run `ollama pull llama3.2:3b` (the model download needs internet and disk space).
3. Ensure Ollama is running. If it is not, run `ollama serve` in another terminal. An address-in-use message usually means it is already running.
4. In Aamor, click **Refresh models**, select the installed model and send a message.

Ollama was not installed on the development machine during verification. The app shows an honest unavailable-model state until a provider is reachable. The integration tests use an isolated streaming provider fixture; real local model quality and speed depend on your hardware. Choose a vision-capable Ollama model for images; text-only models cannot read them.

### Production process

```powershell
npm run build
npm run start
```

Stop the development server before building or starting production on the same port. Keep this working directory, `scripts/`, dependencies, `.env`, database and private upload directory available. The PDF extraction worker is a separate Node process. This is a persistent single-server deployment, not an ephemeral/serverless deployment.

## Included behavior

- Email/password registration, scrypt password hashing, persistent signed sessions, logout and optional Google sign-in.
- Real incremental provider streaming, stop with partial-response persistence, regeneration and editing earlier prompts with later-turn removal.
- Private conversation history, title/content search, rename/delete, pagination and earlier-message loading.
- Markdown, highlighted code with copy buttons, tables and safe external links. Model-generated raw HTML is skipped.
- Owner-scoped PNG/JPEG/WebP/PDF/TXT/Markdown uploads. Images are decoded and normalized before storage. Text-based PDFs are parsed locally; relevant document excerpts enter model context.
- Light/dark theme, model preferences, custom instructions and temperature where supported.
- Usage counts marked as provider-reported or estimated, configurable rate/concurrency limits, loading/error states and keyboard shortcuts.
- Responsive layout, collapsible navigation, Enter to send, Shift+Enter for a newline, Ctrl/Cmd+K for a new conversation and `/` to focus search outside input fields.

## Configuration

Copy values into `.env`; never put provider keys in browser code or `NEXT_PUBLIC_` variables. Restart the server after changes.

| Variable | Default / purpose |
| --- | --- |
| `DATABASE_URL` | `file:./dev.db`, relative to the project root |
| `AUTH_SECRET` | Generated by setup; keep stable and private. Changing it invalidates sessions. |
| `NEXTAUTH_URL` | `http://localhost:3000`; use the exact browser origin, including port |
| `AI_DEFAULT_PROVIDER` | `ollama` |
| `OLLAMA_BASE_URL` | `http://localhost:11434`, reachable from the app server |
| `OLLAMA_CONTEXT_SIZE` | `8192`, upper bound on local context; model capability can lower it |
| `MAX_OUTPUT_TOKENS` | `2048`, reserved output budget |
| `OPENAI_API_KEY` | Optional; enables configured OpenAI models |
| `OPENAI_MODELS` | Comma-separated allowlist, default `gpt-4.1-mini` |
| `ANTHROPIC_API_KEY` | Optional; discovers accessible Anthropic models |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Optional Google OAuth credentials |
| `UPLOAD_DIR` | `storage/uploads`, private path outside `public/` |
| `MAX_UPLOAD_SIZE_MB` | `10` per file, server-clamped to 1–20 |
| `MAX_REQUEST_SIZE_KB` | `256` for JSON chat requests |
| `CHAT_RATE_LIMIT` | `20` requests per minute per user |
| `CHAT_CONCURRENT_LIMIT` | `1` active generation per user |
| `CHAT_TIMEOUT_MS` | `120000` maximum generation duration |

Cloud providers incur their own charges and receive the message context and included attachments. Selecting Ollama keeps inference on the configured Ollama host. Usage estimates are approximate and are not a billing statement. Cloud API credentials were not configured for live verification; protocol parsers are covered by tests. Some cloud models use fixed temperature settings.

For Google OAuth, register `http://localhost:3000/api/auth/callback/google` as the development redirect URI and set both credentials. Only verified Google emails are accepted. Existing password accounts are not automatically linked to a Google identity. Google OAuth needs your own configuration and was not live-tested.

## Data, limits and security

SQLite stores users, hashed passwords, conversations, messages, preferences, attachment metadata/extracted text and token usage. Files are stored under private UUID keys and served only after an owner check. Each route derives identity from the authenticated session. Browser-supplied user IDs are not trusted. Mutations require the configured origin; authentication uses NextAuth CSRF protection.

Uploads accept only supported matching file formats, default 10 MB per file. Images are limited to 25 million decoded pixels and resized within 1280×1280. PDF extraction has a 20-second deadline and bounded Node heap/output; only the first 20 pages are considered. Scanned or encrypted PDFs are unsupported. This is excerpt retrieval, not a vector database or OCR system. Pending uploads expire after 24 hours and are cleaned when the upload API is accessed. Settings also offers removal of unused uploads.

Context keeps system instructions and the most recent turns within a conservative byte-based budget. Large inputs can be truncated; older turns can fall out of context. A limited number of recent images are retained according to the model budget, with omission notes for excluded older images. Usage estimates and image reserves are approximations, not provider tokenizers.

Passwords use salted scrypt and timing-safe verification. APIs bound request bodies, hashing/upload concurrency and provider output; responses avoid exposing secrets or internal errors. Security headers restrict framing and content loading. The CSP permits inline scripts/styles needed by this implementation; a stricter nonce policy is a potential deployment hardening step.

**Deployment boundary:** rate limits, generation locks and cancellation state are in memory. Run one persistent app process. Multiple replicas need shared rate limits/locks/cancellation, a shared database and shared private file storage. Before exposing a public signup service, add operational monitoring, email verification/recovery, abuse controls and a backup/retention policy. The app does not currently offer password reset, email verification, account deletion UI or enterprise tenancy.

Conversation deletion removes database records and attempts physical file cleanup. A filesystem failure or crash can leave unreferenced files; monitor storage and reconcile those during maintenance. Local files and SQLite are not encrypted by the app: use OS disk encryption and restrict filesystem access. Back up the SQLite database and upload directory together while the app is stopped; preserve `.env` securely. Never commit or share live `.env`, `dev.db`, `storage/` or database backups.

## Validation

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
npm audit
```

End-to-end tests require a production build. They start a separate Next.js process with a temporary database, private upload directory and deterministic HTTP provider. They cover authentication, cross-user isolation, incremental streaming, persistence, search, retry/edit, private text/PDF uploads, cancellation, concurrency, timeout and safe provider failures. Your local account and database are not used by these tests.

## Project map

- `app/`: pages and authenticated API routes.
- `components/`: chat, history, composer, Markdown, settings and authentication UI.
- `lib/auth/`: password/session/OAuth handling.
- `lib/ai/`: provider interface, Ollama/OpenAI/Anthropic adapters, streaming parsers and context budgeting.
- `lib/chat/`: server-side conversation generation and cancellation.
- `lib/files/`: validation, private storage, extraction and excerpt selection.
- `lib/db/`, `prisma/`: database access, schema and committed migrations.
- `tests/`: unit, database and HTTP integration tests.
- `docs/implementation.md`: phase completion record.

## Troubleshooting

- **No models:** ensure Ollama is running, pull a model, check `OLLAMA_BASE_URL`, then Refresh models. In a container, localhost means that container, not your host.
- **Origin rejected / sign-in trouble:** use `localhost` consistently and set `NEXTAUTH_URL` to the exact URL. Restart after environment changes; clear stale cookies if the authentication secret changed.
- **Database errors:** run `npm run setup` from the project root. Do not delete an existing database to repair a migration issue.
- **Slow or timed-out responses:** use a smaller model, lower the context/output budget or raise the bounded timeout. A stopped response remains in history.
- **Unsupported image:** select a vision-capable model. Images are not silently submitted to text-only models.
- **PDF extraction error:** use a text-based PDF or paste the relevant text. Scanned pages require OCR outside this app.
- **Port 3000 occupied:** stop the other server or choose a different port and update `NEXTAUTH_URL` accordingly.

The app's name is **Aamor**. The existing project directory remains `cedar-chat` to preserve local paths.
